# Requirements 1.0 — QuizVK

## 1. Назначение
Quizzy — MVP веб-приложения для создания и прохождения интерактивных викторин.
Автор готовит вопросы, запускает сессию, а участники подключаются по коду комнаты,
отправляют ответы и получают результат. Система сохраняет ответы и автоматически
начисляет баллы.

## 2. Пользователи
- Автор викторины — создаёт квиз, запускает сессию, видит статистику.
- Участник викторины — подключается по коду комнаты, отвечает, видит результат.

## 3. Функциональные требования

| ID | Требование | Критерий приемки | Статус |
|----|------------|------------------|--------|
| FR-01 | Пользователь должен зарегистрироваться с именем, email и паролем. | При корректных данных создаётся учётная запись. | Реализовано |
| FR-02 | Пользователь должен войти по имени и паролю. | При верных данных создаётся сессия; при неверных выводится ошибка. | Реализовано |
| FR-03 | Автор должен создать квиз с метаданными и вопросами. | После сохранения API возвращает id, квиз виден автору. | Реализовано |
| FR-04 | Вопрос поддерживает текст, изображение, баллы и один или несколько правильных вариантов. | Вопрос хранит варианты, признак множественного выбора и баллы. | Частично |
| FR-05 | Автор запускает сессию и получает уникальный код комнаты. | Создаётся Session со статусом Waiting или Active и уникальным кодом. | Частично |
| FR-06 | Участник подключается к незавершённой сессии по коду. | При существующем коде открывается прохождение; при неверном — ошибка. | Реализовано |
| FR-07 | Участник отправляет ответ на вопрос. | Система принимает список ID вариантов, сохраняет ParticipantAnswer и возвращает результат. | Реализовано |
| FR-08 | Баллы начисляются только при полном совпадении выбранных и правильных вариантов. | При совпадении начисляются баллы вопроса, иначе 0. | Реализовано |
| FR-09 | Автор видит результаты и статистику по своим квизам. | Статистика показывает число сессий, участников и средний балл. | Частично |
| FR-10 | Система отдаёт таблицу лидеров сессии. | API возвращает пользователей и сумму баллов по убыванию. | Реализовано |

## 4. Нефункциональные требования

| ID | Требование | Критерий приемки |
|----|------------|------------------|
| NFR-01 | MVP собирается одной командой из решения. | `dotnet build QuizMvp.sln` завершается с кодом 0. |
| NFR-02 | MVP запускается локально без отдельного сервера БД. | В `appsettings.json` используется SQLite `Data Source=quizapp.db`. |
| NFR-03 | Ответ `SubmitAnswer` является машинно-проверяемым JSON. | Содержит `isCorrect`, `points`, `message` или ошибку. |
| NFR-04 | Базовый контур качества фиксирует предупреждения сборки. | В карточке доказательств перечислены предупреждения и план. |
| NFR-05 | MVP не требует PostgreSQL и отдельного production WebSocket для текущей контрольной точки. | Baseline использует SQLite и SignalR. |

## 5. Связи требований
- FR-01 и FR-02 — база для всех авторизованных сценариев.
- FR-03, FR-04 — подготовка квиза, связаны с FR-05.
- FR-05 — запуск сессии, связан с FR-06 и FR-10.
- FR-07, FR-08 — ядро прохождения, связаны с FR-09 и FR-10.

## 6. Что не подтверждено текущим набором
Production-развёртывание, нагрузочная устойчивость, безопасность production-уровня,
исключение повторных отправок ответа, интеграция с PostgreSQL, поведение в реальном
внешнем контуре. Эти пункты не считаются выполненными на основании спецификации
или успешной сборки.
