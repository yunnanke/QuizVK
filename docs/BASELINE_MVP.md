# Baseline MVP — QuizVK

## 1. Назначение
Зафиксировать минимальный, но связный набор функций, при котором викторина
работает от создания до результата в едином локальном сценарии.

## 2. Обязательно для MVP

| Блок | Состав |
|------|--------|
| Аутентификация | регистрация (FR-01), вход (FR-02) |
| Квиз | создание квиза с вопросами (FR-03), вопросы с вариантами (FR-04) |
| Сессия | запуск, код комнаты, статус Waiting/Active (FR-05) |
| Подключение | вход участника по коду (FR-06) |
| Ответы | приём ответа, сохранение ParticipantAnswer (FR-07) |
| Оценка | баллы только при полном совпадении (FR-08) |
| Результаты | статистика автора (FR-09), leaderboard сессии (FR-10) |
| Realtime | SignalR |
| Хранение | SQLite через EF Core, файл `quizapp.db` |
| Запуск | локальный, без отдельного сервера БД |

## 3. Резерв будущего продукта

| Не входит в baseline | Комментарий |
|----------------------|-------------|
| PostgreSQL | не является обязательством текущей версии |
| Production-миграции | отдельное решение команды |
| Отдельный WebSocket-контур | SignalR остаётся текущей реализацией |
| Частичные баллы, штрафы, сложные типы оценки | полное совпадение — текущее правило |
| Модерация лобби | вне MVP |
| Экспорт отчётов, расширенная аналитика | вне MVP |

## 4. Основной сценарий
Автор входит в систему → создаёт викторину с вопросами и правильными вариантами →
запускает сессию и передаёт участникам код комнаты → участник подключается по коду
и получает вопросы → отправляет выбранные варианты → система сравнивает наборы,
сохраняет ответ, начисляет баллы → результаты доступны автору и участнику.

## 5. Критерии готовности MVP
- FR-01…FR-10 в статусе «Реализовано» либо обоснованно «Частично».
- NFR-01…NFR-05 выполняются.
- Сборка `QuizMvp.sln` — 0 ошибок.
- Предупреждения сборки зафиксированы и имеют план устранения.
