# ADR-001: Выбор технологического стека и границ инфраструктуры QuizVK

- Статус: принято для MVP
- Дата: 19.10.2026
- Авторы: Матвеева Ю. П., Голубев Е. Е.
- Проект: QuizVK (MVP Quizzy)

## Контекст

QuizVK — веб-приложение для создания и прохождения интерактивных квизов. Основной сценарий MVP:

1. Автор регистрируется и входит в систему.
2. Автор создаёт квиз, вопросы и варианты ответов.
3. Автор запускает сессию и получает код комнаты.
4. Участник подключается по коду.
5. Участник отправляет ответ.
6. Система проверяет ответ, начисляет баллы и сохраняет результат.

Для MVP важны простой локальный запуск, отсутствие обязательной серверной инфраструктуры и возможность проверять основную логику автоматическими тестами.

## Решение

Для MVP используется следующий стек:

- Backend: C# и ASP.NET Core MVC на .NET 8.
- Хранение данных: SQLite через Entity Framework Core.
- Обмен событиями в рамках приложения: SignalR.
- Клиентская часть: HTML, CSS, JavaScript.
- Сборка и зависимости: .NET SDK и NuGet.
- Автоматические проверки: `QuizMvp.LogicTests` и GitHub Actions.
- Основная проверяемая логика: `AnswerScoringService.Score`.

Модель исполнения — серверное веб-приложение. ASP.NET Core принимает HTTP-запросы, обрабатывает маршруты, сессии и авторизацию. SignalR обслуживает событийные подключения по маршруту `/quizHub`. SQLite используется как локальное файловое хранилище; база создаётся при запуске приложения.

## Текущее состояние MVP

На текущем этапе не требуется:

- отдельный сервер PostgreSQL;
- отдельный WebSocket-сервер;
- Docker-инфраструктура;
- облачное хранилище;
- распределённое кэширование;
- сложная аналитика;
- горизонтальное масштабирование.

SQLite выбран потому, что база хранится локально в файле `quizapp.db`, не требует отдельной установки и позволяет воспроизводимо запускать приложение в учебной среде.

SignalR подключён внутри ASP.NET Core-приложения. Отдельная инфраструктура для WebSocket не требуется, так как число участников и нагрузка MVP ограничены учебным сценарием.

## Рассмотренные альтернативы

### PostgreSQL

PostgreSQL не используется в MVP, потому что требует отдельного сервера, настройки подключения, миграций и хранения учётных данных. Это увеличивает сложность запуска и снижает воспроизводимость в учебной среде.

PostgreSQL следует рассмотреть при появлении хотя бы одного из условий:

- несколько экземпляров приложения используют общую базу данных;
- требуется развёртывание для реальных пользователей;
- SQLite становится ограничением по параллельной записи;
- необходимы резервное копирование, роли БД и централизованное администрирование;
- появляются сложные запросы аналитики и большой объём результатов.

Переход на PostgreSQL должен быть оформлен отдельным ADR и задачей: выбрать хостинг, способ хранения секретов, миграции EF Core, резервное копирование и стратегию переноса данных.

### Отдельный WebSocket-сервер

Отдельный WebSocket-сервер не используется, так как SignalR уже обслуживает событийные подключения внутри ASP.NET Core.

Его выделение может понадобиться при условиях:

- большое число одновременных сессий;
- необходимость масштабировать события независимо от HTTP-приложения;
- несколько экземпляров приложения должны доставлять события одним участникам;
- требуется внешний брокер сообщений или backplane.

До появления этих условий события сессии обслуживаются текущим SignalR hub `/quizHub`.

## Последствия решения

Положительные последствия:

- приложение запускается локально с .NET SDK;
- не нужен внешний сервер БД;
- основной сценарий доступен в учебной среде;
- правило начисления баллов можно тестировать без SQLite, сети и SignalR;
- CI может выполнять сборку и LogicTests без специальной инфраструктуры.

Ограничения:

- SQLite подходит для MVP, но не является целевым решением для масштабируемой многопользовательской поставки;
- текущий SignalR-подход не подтверждает готовность к высокой нагрузке;
- пакетные версии должны поддерживаться совместимыми с целевой версией .NET;
- перед поставкой требуется отдельно решить вопросы хранения секретов, HTTPS, резервного копирования и миграций БД.

## Инструментальный контур

| Позиция | Средство | Статус |
|---|---|---|
| Сборка | `dotnet restore`, `dotnet build` | Используется |
| Зависимости | NuGet, `PackageReference` в `.csproj` | Используется |
| Тестирование | `QuizMvp.LogicTests` | Используется |
| Статический анализ | nullable-аннотации и предупреждения компилятора | Используется частично |
| Динамическая диагностика | логирование ASP.NET Core, отладчик Visual Studio/.NET | Используется частично |
| Профилирование | `dotnet-counters` или `dotnet-trace` | Запланировано |
| CI | GitHub Actions, `quality-gate.yml` | Настроено, требует подтверждённого запуска |

## Связанные требования

- FR-07: участник отправляет ответ на вопрос.
- FR-08: баллы начисляются только при полном совпадении выбранных и правильных вариантов.
- NFR-01: решение собирается в воспроизводимом окружении .NET.
- NFR-02: MVP работает без серверной PostgreSQL.
- NFR-03: результат отправки ответа однозначно интерпретируется клиентом.

## Пересмотр решения

ADR должен быть пересмотрен при переходе от учебного MVP к развёртыванию для реальных пользователей, при появлении требований к масштабированию, при подключении PostgreSQL, выделении событийной инфраструктуры или изменении основной версии .NET.
