# Инженерный регламент — Quizzy

## 1. Путь изменения
задача → ветка → код и документация → локальная сборка и применимые проверки →
pull request или merge request → review по значимости → слияние.

## 2. Существенные изменения
Существенным считается изменение:
- требований;
- модели данных;
- алгоритма начисления баллов;
- авторизации;
- внешнего ресурса;
- публичного контракта API.

Для существенных изменений review обязателен.

## 3. Правила работы
- Перед изменением фиксируется задача с целью, затрагиваемыми требованиями и рисками.
- Изменение выполняется в отдельной ветке.
- Код, тесты и документация изменяются согласованно.
- До слияния выполняются сборка и проверки, применимые к изменению.
- Результат и известные риски фиксируются в PR/MR.

## 4. Ограничения baseline
В baseline нельзя молча добавлять PostgreSQL, отдельный WebSocket или иной крупный
ресурс. Такое изменение требует отдельного решения команды.

## 5. Именование веток и коммитов
- Ветки: `feature/<кратко>`, `fix/<кратко>`, `docs/<кратко>`, `refactor/<кратко>`.
- Коммиты: `<тип>(<область>): <краткое описание>`.
  Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`, `ci`.

## 6. Pull Request
- Заголовок кратко отражает суть.
- В описании: что сделано, как проверить, ссылка на Issue, затрагиваемые FR/NFR.
- Для существенных изменений — минимум один approval.
- Обсуждения в PR должны быть закрыты до merge.

## 7. Слияние
- Только после сборки и применимых проверок.
- Для существенных изменений — после review.
- Ветка удаляется после merge.
