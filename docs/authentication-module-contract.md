# Контракт модуля регистрации и входа

## Назначение и граница

Модуль реализует регистрацию учётной записи и проверку имени с паролем. Его публичная граница — `QuizMvp.Authentication.IAuthenticationModule`. Веб-слой передаёт запрос и получает типизированный исход. Модуль не формирует HTTP-ответы, не обращается к сессии и не зависит от MVC.

Потребитель контракта — `QuizMvp.Controllers.AccountController`. Рабочая реализация — `QuizMvp.Services.AuthenticationModule`; точка подключения — регистрация `IAuthenticationModule` в `Program.cs`.

## Операции

| Операция | Вход | Результат | Ошибки и порядок | Побочные эффекты и владение |
|---|---|---|---|---|
| `RegisterAsync(request, cancellationToken)` | Имя, email, пароль и роль; строки могут быть `null` из-за формы | `Registered` и данные аккаунта; `Disabled`; `InvalidPassword`; `UsernameAlreadyExists` | Сначала проверяется доступность регистрации, затем пароль (не менее 8 символов, буква Unicode и специальный символ), затем занятость имени; после этого создаётся запись. Отмена операции передаётся EF Core и может завершить вызов `OperationCanceledException`. Ошибка хранилища передаётся вызывающему коду | При успехе создаёт одну запись пользователя. Контекст БД и записью владеет модуль. Модуль возвращает только ID, имя и роль для сессии |
| `AuthenticateAsync(request, cancellationToken)` | Имя и пароль; строки могут быть `null` | `Authenticated` с данными аккаунта либо `InvalidCredentials` | Ищется имя, затем проверяется пароль. Отсутствующее имя, пустой пароль, неизвестный пользователь и неверный пароль дают общий исход `InvalidCredentials`. Отмена передаётся EF Core | Не меняет данные. Создание веб-сессии остаётся за контроллером |
| `RegistrationEnabled` | Нет | Текущее значение настройки `Authentication:RegistrationEnabled` | Ошибка неверной конфигурации обнаруживается при создании настройки приложения | Только чтение настройки; записью владеет конфигурация приложения |

## Пример использования

```csharp
var result = await module.AuthenticateAsync(
    new LoginRequest(username, password), cancellationToken);

if (result.Status == AuthenticationStatus.Authenticated && result.Account is { } account)
{
    // Потребитель приложения создаёт сессию из account.Id, account.Username и account.Role.
}
```

## Гарантии и известные ограничения

- Контракт не раскрывает `User`, `ApplicationDbContext`, EF Core или MVC типы.
- Роль при регистрации без заданного значения получает `Participant`, как и в прежнем поведении приложения.
- В текущей реализации пароль хешируется однократным SHA-256 в Base64 для сохранения совместимости с существующими записями. Это ограничение MVP и не является рекомендацией для production.
- Проверка уникальности относится только к имени пользователя. Текущая схема не запрещает повторяющийся email.
- Валидация формата email находится за пределами данного контракта. При регистрации пароль должен иметь длину не менее 8 символов, содержать хотя бы одну Unicode-букву и хотя бы один знак пунктуации или символ Unicode. Пробелы и цифры специальными символами не считаются; правило проверяется модулем до записи пользователя.
- Тестовая подстановка подтверждает работу потребителя на той же границе, но не моделирует реальную БД, хеширование или устойчивость хранения.
